## 背景

資料庫管理課的期末專案，題目是設計一個有實際資料庫支撐的管理系統。我們做的是智慧販賣機管理系統，分成三種角色：管理者（Manager）、員工（Staff）與消費者（Consumer），各自有不同的操作權限。

除了基本的新增、查詢、修改、刪除，課程要求把上課學到的交易管理概念實際做出來：失敗回復、並行控制與安全控制。

## 我做了什麼

- 參與全端功能開發與除錯，後端用 Spring Boot，前端用原生 HTML / JS / CSS
- 實作失敗回復（Failure Recovery）：後端交易與前端自動重試
- 實作並行控制（Concurrency Control）：樂觀鎖與悲觀鎖
- 實作安全控制（Security Control）：密碼雜湊、輸入檢查、登入逾時處理

## 技術重點

### 交易與失敗回復

後端用 `@Transactional` 包住一次購買會動到的多張表，任何一步失敗就整筆回滾，不會出現「扣了庫存但沒有訂單」的狀況。前端則在請求失敗時用指數退避（exponential backoff）重試，避免網路短暫不穩就讓使用者看到錯誤。

### 兩種鎖的取捨

- **樂觀鎖**：資料表加上 `version` 欄位，更新時檢查版本是否被別人改過，適合衝突少的管理操作
- **悲觀鎖**：用 `SELECT ... FOR UPDATE` 先鎖住該筆庫存，適合多人同時購買同一商品這種衝突機率高的情境

樂觀鎖的更新語句大致長這樣（示意）：

```sql
UPDATE product
SET stock = stock - 1, version = version + 1
WHERE id = ? AND version = ?;
```

### 安全控制

密碼用 BCrypt 雜湊後才存進資料庫；所有輸入經過 `InputSanitizer` 檢查；後端回傳 401 時，前端自動登出並導回登入頁。

### 程式風格

全程使用 `JdbcTemplate` 直接寫 SQL，不使用 JPA，讓每一句查詢都看得見；搭配建構子注入、統一的 `ApiResponse<T>` 回傳格式，以及用 `ResponseStatusException` 處理錯誤。
