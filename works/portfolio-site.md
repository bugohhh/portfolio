## 背景

之前做網頁的方式是 Vibe Coding：跟 AI 來回對話，把「這一頁」做出來。問題是每做一頁都要重新解釋一次風格與結構，做出來的頁面也長得不太一樣。

這次想反過來：先寫好一套規則，讓 AI 讀完規則就知道這個專案該怎麼繼續做下去。之後要新增作品，只要給它素材，它就能照同一套格式產出新頁面。

## 我做了什麼

- 寫了 `CLAUDE.md`，規定專案目的、技術限制、目錄結構、視覺風格、作品資料欄位、文章段落、標籤詞彙與修改規則
- 把網站拆成「版面」與「內容」：版面只有 `index.html` 與 `work.html` 兩個模板，內容放在 `works/` 底下
- 自己寫了一個小型 Markdown 解析器 `md.js`，只支援規則裡列出的語法
- 寫了 `tools/check.py`，自動檢查作品資料是否符合規則
- 部署到 GitHub Pages

## 技術重點

### 新增作品不需要寫 HTML

每件作品只有兩樣東西：`works/works.json` 裡的一筆 metadata，以及 `works/<slug>.md` 的內文。內頁 `work.html` 會讀網址上的 `?id=`，去抓對應的資料與內文再渲染。作品編號（壹、貳、參…）則依清單順序自動產生。

```
works/
├── works.json              ← 標題、摘要、期間、標籤…
└── smart-vending-machine.md ← 只有內文
```

### 用程式檢查規則

規則寫在文件裡，AI 不一定每次都照做，所以我把可以機械化檢查的規則寫成 `check.py`：必填欄位、`slug` 格式、摘要字數、標籤是否在詞彙表、文章是否有四個固定段落、CSS 有沒有寫死顏色等。`CLAUDE.md` 要求每次修改後都要跑一次。

### 刻意不用框架

只用 HTML、CSS 與原生 JavaScript，沒有建置步驟，push 上去就是網站。限制越少，AI 越容易亂加東西，所以規則裡明確禁止加入 npm 套件與框架。

## 反思

寫規則比寫網頁難。一開始的規則太模糊（例如「風格要一致」），AI 還是會自己發揮；後來改成具體的色票表、固定段落標題和欄位字數，產出才穩定下來。

> 好的規則不是寫給 AI 看的提示詞，而是任何人接手都能照做的施工規範。
