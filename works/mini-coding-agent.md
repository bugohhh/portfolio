## 背景

平常都在用 AI coding 工具，但不太清楚它們內部怎麼運作。為了弄懂 agent 到底是怎麼「自己決定下一步」，我決定用 Python 從零寫一個最小可用的版本 `mini_harness.py`，再一步步加功能。

## 我做了什麼

- 實作 agent loop：把使用者需求送給模型，模型決定要不要呼叫工具，執行後把結果送回去，直到任務完成
- 設計工具：執行 bash 指令、讀檔、寫檔、以 `str_replace` 局部修改檔案
- 處理 context 管理：對話越來越長時，決定哪些內容要保留給模型
- 透過 Anthropic API 串接模型

## 技術重點

### Agent loop 其實很單純

核心只是一個迴圈：模型回覆中如果有工具呼叫，就執行工具、把結果附加到對話，再呼叫一次模型；沒有工具呼叫就代表完成。真正難的不是迴圈，而是工具與 context 的設計。

### 工具設計決定 agent 的能力

一開始只有「寫整個檔案」，模型改一行也要重寫整份，容易出錯。加入 `str_replace` 之後，模型只需要指定要替換的片段，修改變得精準很多。工具的說明文字寫得好不好，也直接影響模型會不會用對。

## 反思

寫完之後再看其他 AI 工具，就比較知道它們在做什麼取捨。這些經驗也直接用在畢業專題的構想上，例如多個 agent 之間如何分工。
